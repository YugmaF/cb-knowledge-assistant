## When to Use This Runbook

Use the Payment Gateway Certificate Rotation runbook when a TLS certificate used by the cardnet-gateway-adapter or the payment gateway ingress (pay-gw.commbank.example) is within 14 days of expiry, has already expired, or when automated rotation has failed. The payment gateway certificates are the adapter client certificate, the ingress server certificate, and every intermediate certificate in their chains. Since 2026-04-30 payment gateway certificates renew automatically 30 days before expiry; this runbook is the manual fallback.

## Check Certificate Expiry

To check payment gateway certificate expiry, including intermediates:

1. Run `openssl s_client -connect pay-gw.commbank.example:443 -showcerts </dev/null` and note the notAfter date of every certificate in the chain.
2. For the adapter client certificate, run `kubectl -n payments exec deploy/cardnet-gateway-adapter -- keytool -list -v -keystore /etc/cardnet/client.p12` and read "Valid until".
3. Check the certificate inventory dashboard; any payment gateway certificate under 14 days is a SEV3, and an expired one is a SEV1 or SEV2 depending on impact.

## Manual Certificate Rotation Steps

Follow these steps to rotate a payment gateway certificate manually:

1. Generate a new key and CSR in the secrets vault: `vault write pki-payments/issue/cardnet common_name=pay-gw.commbank.example ttl=8760h`.
2. For the adapter client certificate, send the CSR to the CardNet Gateway onboarding portal and wait for the signed certificate (normally 1 hour; ask CardNet Gateway support for an emergency signing during an outage).
3. Get approval from the security on-call engineer for the new certificate; this is an emergency change if an incident is open.
4. Store the certificate and full chain in the vault path `secret/payments/cardnet/`.
5. Roll the cardnet-gateway-adapter: `kubectl -n payments rollout restart deploy/cardnet-gateway-adapter`. For the ingress certificate, update the ingress TLS secret and reload the ingress.
6. Deploy to one canary pod first and confirm successful authorisations for 5 minutes before completing the rollout.

## Verify the Rotation

After payment gateway certificate rotation, confirm the card authorisation success rate is above 98 percent on the payments dashboard, confirm no TLS handshake errors in cardnet-gateway-adapter logs, and re-run the openssl check to confirm the new notAfter date on every certificate in the chain.

## Automated Rotation

The automated payment gateway certificate rotation uses cert-manager with the internal CA and renews leaf and intermediate certificates 30 days before expiry. If automated rotation fails, cert-manager raises an alert to the payments on-call engineer. Check the Certificate resource with `kubectl -n payments describe certificate cardnet-client` before falling back to the manual steps above.

## Escalation

If the CardNet Gateway rejects the new certificate, escalate to CardNet Gateway support through the vendor escalation line and inform the Head of Payments Engineering. Related incidents: INC-2025-006, INC-2025-020, INC-2026-012.
