## Symptoms

Use the Payments-Ledger DB Connection Pool Exhaustion runbook when payments-ledger cannot obtain database connections. Typical symptoms of payments-ledger connection pool exhaustion are: payments-api returning HTTP 503 for transfers, "unable to acquire JDBC connection" or "pool wait timeout" in payments-ledger logs, the PgBouncer client wait queue growing, and ledger database connections near max_connections. Payments-ledger connection pool exhaustion is most likely on salary day and at month-end.

## Immediate Triage

Follow these triage steps for payments-ledger connection pool exhaustion:

1. Declare an incident; any payments-ledger outage affecting transfers is at least SEV2.
2. Check PgBouncer: `psql -h pgbouncer.ledger -p 6432 pgbouncer -c "SHOW POOLS;"`. Note cl_waiting and sv_active.
3. Confirm PgBouncer runs in transaction pooling mode: `SHOW CONFIG;` and check pool_mode = transaction. Session mode gives no multiplexing and caused INC-2026-004.
4. Find long-running queries: `SELECT pid, now() - query_start AS age, query FROM pg_stat_activity WHERE state <> 'idle' ORDER BY age DESC LIMIT 20;`.

## Mitigation Steps

Apply these mitigations for payments-ledger connection pool exhaustion in order, checking the error rate after each:

1. Pause non-critical load: corporate bulk payment jobs and any recently enabled feature flags that call the ledger (for example bulk payee validation).
2. Throttle InstaPay at payments-api to 50 percent using the rate-limit flag `instapay_throttle_pct`.
3. Terminate queries older than 60 seconds that are not salary credit postings: `SELECT pg_terminate_backend(pid) ...`.
4. Do not raise the per-pod pool size blindly. Total connections across all payments-ledger pods must stay under PgBouncer and database limits; raising the pool made INC-2025-015 worse.
5. If the primary database CPU is above 90 percent, move balance queries to the read replica with the flag `ledger_balance_read_replica`.

## Recovery and Verification

Payments-ledger has recovered when payments-api 5xx is below 1 percent for 15 minutes, PgBouncer cl_waiting is zero, and pool wait time is below 100 ms. Resume paused jobs one at a time at reduced concurrency.

## Salary Day Prevention Checklist

Before each salary day and month-end, the payments on-call engineer confirms: the salary-day load test at 5x peak passed including all new features, PgBouncer is in transaction mode, the read replica is healthy, the salary credit batch starts at 05:00, and the change freeze is active.

## Related Incidents

Related payments-ledger connection pool incidents: INC-2025-003, INC-2025-015, INC-2025-023, INC-2026-004, INC-2026-028. Escalate to the database reliability engineer on-call if mitigations do not work within 30 minutes.
